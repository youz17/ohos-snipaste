# 已知限制与候选改进

下面每一条都有实测证据（详见 [README.md](../README.md) 与 [docs/ARCHITECTURE.md](ARCHITECTURE.md)），
不是猜测。标注了代价，供决策。

## 限制 1：贴图不能浮在其它应用之上

- 实测：把文件管理器切到前台后，贴图窗口 `ZOrd` 从 114 变成 `-1`（被隐藏），像素上
  贴图内容被覆盖。
- 原因：`ohos.permission.WINDOW_TOPMOST` 是 normal 级，其能力语义是"置于**本应用**
  其它窗口之上"。
- 候选方案：`window.createWindow({ windowType: TYPE_FLOAT })` +
  `ohos.permission.SYSTEM_FLOAT_WINDOW`（system_basic，**需向华为申请 ACL 受限权限**）。
  顺带能解决限制 2（悬浮窗可设圆角与阴影）。
- 已排除：画中画（`@ohos.PiPWindow`）要求 `XComponent` 视频面，不是贴静态图的路径。

**需要你决定的**：是否去申请 ACL。不申请就接受"贴图在本应用窗口之上、其它应用前台时会盖住"。

## 限制 2：贴图窗口四角有约 40px 圆角

- 实测：`setWindowCornerRadius(0)` 对主窗口报 `1300004`，系统日志写明
  `SetWindowCornerRadius: This is not sub window or float window`。
- 试过的绕法（已放弃）：窗口四周留 56px 透明边距把圆角藏进边距。失败原因是**主窗口画布
  改不成透明**——边距恒为不透明浅灰 `(228,227,232)`，`setWindowBackgroundColor('#01000000')`
  在 resize 前/后各设一次都没用，`'#00000000'` 更会被当成"未设置背景"。
- 候选方案：同上（TYPE_FLOAT）；或接受圆角。

## 限制 3：比较的基点不稳健

- 实测：框选整体偏移 +20px（内容没变）时，基点跳到另一个特征，
  `offset(-683,-77)`、差异 39.42%。
- 原因：基点是"**第一个**非背景像素"，它可能是随裁剪位置一起漂的边框，而非稳定特征。
- 候选方案：把基点当**初值**，再在其邻域内做有界搜索取差异最小的偏移。为避免全量枚举，
  用粗到细两阶段（先 1/8 降采样搜 ±64px，再全分辨率在 ±8px 内细化），预计几十毫秒。
- 要不要改由你定：它偏离了你最初指定的算法，所以没擅自改。

## 限制 4：小选区窗口被系统撑大

- 实测：系统对主窗口有最小尺寸限制，约 `608x136` px。截 200x100 的区域时窗口会被撑到
  608x136，1:1 画图就会露出一圈底色。
- 现状处理：用同一张图放大模糊铺底（`ImageFit.Cover` + `blur(40)`）填补，正常尺寸时该层
  完全不可见。
- 备选：整数倍放大显示（更像"放大镜贴图"，但破坏 1:1）。

## 限制 5：运行时任务栏必然有一个图标，且放不了托盘图标

- 目标（用户原话）：不要任务栏里的应用按钮，要像输入法图标那样常驻在**时间旁边**。
- 实测：`"excludeFromDock": true` 已加到三个 Ability 且被系统读到（`bm dump` 确认），但运行时
  任务栏仍出现我们的图标；干净卸载重装也无效。
- 实测：SDK 里**没有**第三方可用的状态栏/托盘图标 API；`excludeFromMissions` 是 system-only。
- 候选方案（都只能"绕过图标"，不能消除它）：
  1. **通知**作常驻入口：通知中心正是点时钟/托盘那块打开的面板；通知可带按钮，点按钮触发截图。
     代价：应用需在运行时才有通知；且运行期间任务栏图标依旧在。
  2. **全局快捷键**（`inputConsumer`，零权限）：最接近 Snipaste 的手感，点了就截图，
     不需要任何可见入口。代价：同上，进程要在。
  3. 接受现状：任务栏图标就当启动入口。
- 已排除：画中画（要 `XComponent` 视频面）。



| 功能 | 代价 | 备注 |
| --- | --- | --- |
| 全局快捷键唤起截图 | 零权限（`inputConsumer`，API 14+） | Snipaste 最核心的手感；比点任务栏图标顺手 |
| 多贴图管理 | 中 | 透明度、滚轮缩放、一键关全部、贴图列表 |
| 比较入口的 UX 细化 | 小 | 比如在贴图右键菜单里「设为比较基准」，或比较时弹列表选哪一张 |
| `ImageDiff` 单元测试 | 小 | 纯计算逻辑，可脱离设备验证对齐与统计 |

## 待你确认的历史决策

1. 是否申请 `SYSTEM_FLOAT_WINDOW` 的 ACL（见限制 1/2）。
2. 是否做基点对齐细化（见限制 3）。
3. 贴图窗口去掉按钮改右键菜单后，是否需要保留一个最小化的可见操作入口。
